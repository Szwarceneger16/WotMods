# Native value painting and single result coverage in 0.9.10

Min/Max values retain their original numeric text and WN8 figure nodes directly
inside the table cell. A transparent button overlays the same area and draws a
visible olive frame and corner cue. The number no longer depends on a button's
caption painting, which can collapse in the live client even while navigation
still works. Original padding, font sizes and number width remain unchanged.
Financial Min/Max captions use explicit native control-label blocks. Average
remains a normal, noninteractive value. Period, account, revision and DOM ownership
checks continue to protect every source-battle action.

Visible received/recorded coverage has exactly two permitted locations: the
global Results received headline and one generic upper-left badge on each partial
aggregate card. Tables, WN8 labels, Free XP, active sort values and the footer do
not repeat the ratio. A card's single Battles figure is its recorded total, which
matches the existing sort comparator. Metric-specific availability remains in
the existing information help and accessibility labels.

Historical records continue to show their received credit earnings, actual costs
and net values. An entirely unavailable base-credit comparison is omitted; known
zero and income-only/net-only base data remain visible. Row visibility depends on
data availability, not sorting. Costs keep their sorting identity and permanent
source actions on the received row whenever the base comparison is absent.
Finance help explains how an available original full result can supply previously
unsaved base earnings through existing passive cache observation.

A synthetic fixture frozen from the actual 0.9.8 output protects every old metric
through persistence, authoritative all-unknown updates, save/reload and cached
report enrichment. The original Min/Avg/Max XP and WN8 values, received credit
amounts, costs, net balances and other currencies remain identical. Confirmed
post-battle XP bonuses remain protected. No history-wide refetch or estimated
premium-factor backfill is introduced.

Focused UI regressions model the observed unsupported button-caption failure,
verify original numeric-node identity, check visible action cues without hover,
and assert the only allowed ratio locations in all seven interface languages.
Legacy and partial-data cases exercise both source navigation and plain Average.
The original client still requires an in-game visual check; browser doubles do
not execute its renderer. Captures and the legacy fixture use synthetic data.
